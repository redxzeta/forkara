# No Forks Given popup inventory

This inventory is the implementation boundary for focus mode. It was generated from the web source tree by auditing `Dialog`, `AlertDialog`, `api.dialogs.confirm`/browser confirmation fallbacks, both toast managers, confirmation popovers, and other popovers. “Migrated” means focus mode uses an in-layout surface; default mode keeps the existing portal or native shell behavior. Session history, notification coalescing/dismissal, and the confirmation queue are deliberately not persisted.

## Destructive surfaces outside the migrated core

These remain documented and deferred because they are settings/admin/device/desktop lifecycle surfaces rather than the daily coding loop:

- `components/settings/AdvancedSettingsPanel.tsx`: repair local state and browser-session sign-out native confirmations.
- `components/settings/ConversationStorageSettingsPanels.tsx`: delete worktree and permanently delete archived conversation native confirmations.
- `components/useSpacesController.ts`: delete Space confirmation.
- `components/ProjectScriptsControl.tsx`: delete project action `AlertDialog`.
- `components/DevicePanel.tsx`: remote-device shutdown `AlertDialog`.
- `components/RunningChatsQuitDialog.tsx`: desktop quit `AlertDialog`; its native lifecycle handshake must remain independent.

These are not unsolicited notifications and remain popovers: `ProviderUsageLimitRows.tsx`, branch/Git menus in `GitActionsControl.tsx`, `GitDialogChrome.tsx`, project-script menus, `ThemePackEditor.tsx`, `chat/BrowserAnnotationStrip.tsx`, `chat/ContextWindowMeter.tsx`, `chat/environment/EnvironmentRow.tsx`, PR filters/stack popover in `pullRequest/PullRequestListFilters.tsx` and `pullRequest/PullRequestStackPopover.tsx`, terminal controls in `terminal/TerminalChrome.tsx`, and the explicitly opened automation and pull-request route popovers.

## Remaining toast call sites covered by the router

The router intentionally preserves the existing manager call surface for lower-frequency callers too, avoiding split semantics when focus mode is enabled: `AppSnapCoordinator.tsx`, `DebugFeatureFlagsMenu.tsx`, `DevicePanel.tsx`, `FeedbackDialog.tsx`, `ThemePackEditor.tsx`, `automation/AutomationProposalActions.tsx`, settings panels (`AdvancedSettingsPanel`, `AppSnapShortcutControl`, `ConversationStorageSettingsPanels`, `DesktopSettingsPanels`, `ExternalMcpSettingsPanel`, `KeyboardShortcutsSettingsPanel`, `ProvidersSettingsPanel`, `XIntegrationSettingsPanel`), `useGitProgressToastPreview.ts`, `useSpacesController.ts`, `routes/-automations.shared.tsx`, and `routes/_chat.settings.tsx`. Their dialogs/editors remain deferred, but any notification they emit is non-popup history in focus mode.

## Default-mode layering rule

Top-center and anchored toast positioners use the notification layer (`z-40`), below dialog and alert-dialog backdrops/viewports (`z-50`). A visible toast therefore cannot intercept pointer or keyboard interaction with an active user-invoked dialog.
